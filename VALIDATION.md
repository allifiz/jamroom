The persistence test queries actual `playlist_items` rows and recreates browser contexts. The owner-offline test verifies that a second authenticated user can issue a playing state without the owner browser. Because the official iframe cannot load here, that test does **not** establish audible playback. The separate opt-in iframe test compares actual YouTube API player states and positions when network access is available.

The local backend uses actual PostgreSQL records and actual Supabase Auth/Realtime protocols, not frontend mocks. SQL-only tests contain explicit auth-claim and Realtime harness helpers; live integration tests use the official running services. Test-created rooms are cleaned up. Random test Auth accounts remain in the local development database.

YouTube metadata falls back to video-ID labels because the official oEmbed endpoint is also blocked. Thumbnail failures render a music-icon fallback. No failed metadata request or unavailable player is represented as successful playback.

## Reproduce

See README for commands and environment requirements. `npm run backend:start` starts the tested lightweight local stack and preserves an existing database. `.env.local` and `dev/.env` are ignored and must never be committed. Hosted test runs should use confirmed dedicated accounts and a separate test project.

The saved cloud draft contains `install_script`, `start_skill`, and YouTube network domain additions. Saving a draft does not activate network rules, publish the environment, or deploy the app. Review/save those settings and publish the environment to make the network configuration available, then retry the opted-in live YouTube test. Vercel additionally requires the hosted Supabase URL/client key and all SQL migrations in filename order; the optional YouTube Data API key stays server-only.
